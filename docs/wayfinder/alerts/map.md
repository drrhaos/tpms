## Destination

В TPMS Monitor реализованы двухуровневые тревоги — «Внимание» (отклонение, можно ехать) и «Неисправность» (ехать нельзя): неисправность — несмахиваемое уведомление, красное всплывающее окно поверх всего и звуковой сигнал; охват — шины и отказ мониторинга; все устройства, эталон Teyes. Готово = код + unit-тесты + чек-лист ручной проверки на Teyes (проверяет человек).

## Notes

- Домен: Android foreground-сервис, уведомления, оверлей; текущая логика тревог — `AlertEvaluator`, `WheelCrossCheck`, `AlertNotificationPolicy`/`Book`, `AlertNotifier`, `MonitoringHealthNotifier` (см. `AGENTS.md`).
- Режим: **решения + код** (переопределение по умолчанию): тикет принимает решение, после чего код меняется в рамках карты — отдельными task-тикетами, когда решения позволят их нарезать.
- Gradle/Android SDK в Linux-VM нет: unit-тесты пишем здесь, запускает человек на Windows.
- Скиллы для сессий: `grilling` (вопросы по-русски через AskUserQuestion); границы модулей — `codebase-design`; вид окон — `prototype`.
- Исходные позиции, собранные при составлении карты (2026-11-17), — стартовая точка для тикетов, не решения:
  - «Неисправность»: критически низкое давление, быстрая потеря давления, потеря датчика, мониторинг не работает. Остальное (высокое давление, перегрев, батарея, умеренно низкое) — «Внимание».
  - Неисправность: красное окно поверх всего до кнопки «Понятно»; затем напоминание окном + звуком с настраиваемым интервалом; ухудшение — сразу.
  - Внимание: жёлтое окно + короткий сигнал, окно скрывается само.
  - Системное уведомление обоих уровней живёт, пока проблема есть, и не смахивается.
  - «Без звука 30 мин» — только для «Внимания».
  - Разрешение «Поверх других окон» — обязательный шаг онбординга + запасной путь (full-screen intent, heads-up).

- [Как живёт тревога — «Понятно», напоминания, смена уровня, несколько колёс](05-alert-lifecycle.md): одно красное окно со списком, сигнал каждые 30 с до «Понятно» (окно / уведомление / главный экран), напоминание через интервал 1–30 мин (по умолчанию 5), ухудшение — сразу; «Внимание» — жёлтое окно 10 с раз на тип, «Без звука» только для него; уведомления несмахиваемы, только живые данные, пауза при выключенном экране, новая поездка — всё заново.

- [Какие состояния — «Неисправность», какие — «Внимание», и с какими порогами](01-severity-classification.md): FAULT = давление < 65 %, `PRESSURE_DROP` (утечка ≥ 15 с, −30 кПа/10 мин, перекос оси ≥ 40 кПа), перегрев ≥ порог + 15 °C, потеря датчика, мониторинг не работает; ATTENTION = < 80 %, > 135 %, ≥ 85 °C, батарея; модель `AlertType` + `AlertLevel`, пороги — константы.

- [Как гарантированно проиграть сигнал тревоги поверх музыки на магнитоле](04-alarm-sound.md): звук канала ненадёжен (молчит без ведома приложения); свой `AlertSoundPlayer` на `USAGE_ALARM` + фокус `MAY_DUCK`, свои звуки в `res/raw`, канал беззвучный; громкость в «Проверке системы»; микшер FYT — проверить на железе.
- [Как сделать уведомление о тревоге несмахиваемым на Android 9–15 и Teyes](02-persistent-notification.md): `setOngoing` (на 9–13 несмахиваемо, на 14+ — тихая перепубликация по delete intent), `fullScreenIntent` во всех публикациях тревоги, текст тревоги и в постоянном уведомлении; главный носитель на Teyes — окно поверх всего.
- [Как показать окно тревоги поверх всего на Teyes и Android 9–15](03-overlay-window.md): `TYPE_APPLICATION_OVERLAY` с SAW работает на 9–15 поверх любых приложений, кнопка нажимается (`FLAG_NOT_FOCUSABLE`); без SAW — только heads-up/FSI; новый `AlertOverlayController`, состояние окна вне процесса; риск — камера заднего хода FYT.
