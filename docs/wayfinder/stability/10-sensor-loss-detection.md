## Question

Ресивер AA55 бесконечно повторяет последнее значение каждого слота (см. [Что означают байты статуса и коды шин в протоколе 55AA](03-aa55-status-flags.md)), поэтому `checkSensorTimeouts` по времени прихода кадров не видит ни мёртвый датчик, ни датчик, уснувший на стоянке, — и наоборот может давать ложный SENSOR_LOST при паузах в потоке. Чем определять потерю датчика: бит статуса `0x20`, неизменность значения N минут, периодический запрос ID (`0x07` → кадр `09`), их комбинация? Как это работает для HID-донглов, и как отображать «данные старые», а не «тревога».

## Подсказки

- Из [Нужно ли подтверждать тревогу перед показом](05-alert-confirmation.md): **сужен.** Тревога SENSOR_LOST решена там (бит `0x20` → сразу, снятие первым чтением без бита); таймаут по приходу кадров больше не даёт SENSOR_LOST. Здесь остаётся только критерий состояния «данные старые» (неизменность значения N минут, запрос ID `0x07`, поведение HID, судьба настройки `sensorTimeoutMs` — после реализации тикета 05 она ни на что не влияет, но всё ещё видна в настройках и экспорте) и его показ — это не тревога.

- Из [Откуда фантомная запаска SP в v1.1.3](01-phantom-spare.md): мусорные `SENSOR_XX` сейчас получают ложный SENSOR_LOST и переводят всё приложение в Alert.
- Из [Как защитить парсер AA55 от мусорных кадров](04-aa55-parser-hardening.md): «нет сигнала» = бит `0x20`, приходит флагом `noSignal`; кадр `09` разбирается, `0x07` шлётся при открытии.

## Resolution

Grilling с drhaos, 2026-10-24. «Данные старые» — состояние, не тревога (тревоги — тикет 05).

**Критерий по колесу:**
- **AA55/Deelife** — своего критерия нет: `timestamp` = время прихода кадра, а ресивер повторяет кэш слота, поэтому время последней передачи датчика неизвестно, а замершее значение на стоянке — норма. Мёртвый датчик отмечает сам ресивер битом `0x20` → SENSOR_LOST (05). Периодический `0x07` не вводим (привязка слотов — тикет 11).
- **HID** — колесо «старое», если от датчика нет передачи > **15 мин** (константа, не настройка). `timestamp` у HID честный; порог выше обычного интервала передачи на стоянке.

**Общее «данные устарели»** (шапка, виджет) считается **по соединению**, а не по возрасту самого свежего датчика: нет живой сессии (реконнект, донгл отключён, данные восстановлены из снимка) или у потоковой сессии нет валидных кадров > 60 с. Ложное «устарели» на HID-стоянке уходит.

**Показ:** старое колесо приглушено (серым) на плитке приложения и виджета, значения остаются, подпись «N мин». Активная тревога важнее приглушения: цвет тревоги остаётся, снимает её только новое чтение (05); подпись «N мин» показывается и тут.

**Где живёт:** чистая функция в `domain/` (рабочее имя `SensorFreshness`, рядом с `MonitoringHealthPolicy`): устаревание колеса по протоколу + общее устаревание по соединению; UI обновляется существующим тиком 30 с. Датчики из снимка до открытия сессии покрыты общим «устарели».

**`sensorTimeoutMs`** удаляется из UI, `SettingsStore` и экспорта; при импорте ключ `sensor_timeout_ms` молча игнорируется.
