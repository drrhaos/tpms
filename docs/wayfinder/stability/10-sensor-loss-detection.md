## Question

Ресивер AA55 бесконечно повторяет последнее значение каждого слота (см. [Что означают байты статуса и коды шин в протоколе 55AA](03-aa55-status-flags.md)), поэтому `checkSensorTimeouts` по времени прихода кадров не видит ни мёртвый датчик, ни датчик, уснувший на стоянке, — и наоборот может давать ложный SENSOR_LOST при паузах в потоке. Чем определять потерю датчика: бит статуса `0x20`, неизменность значения N минут, периодический запрос ID (`0x07` → кадр `09`), их комбинация? Как это работает для HID-донглов, и как отображать «данные старые», а не «тревога».

## Подсказки

- Из [Нужно ли подтверждать тревогу перед показом](05-alert-confirmation.md): **сужен.** Тревога SENSOR_LOST решена там (бит `0x20` → сразу, снятие первым чтением без бита); таймаут по приходу кадров больше не даёт SENSOR_LOST. Здесь остаётся только критерий состояния «данные старые» (неизменность значения N минут, запрос ID `0x07`, поведение HID, судьба настройки `sensorTimeoutMs` — после реализации тикета 05 она ни на что не влияет, но всё ещё видна в настройках и экспорте) и его показ — это не тревога.

- Из [Откуда фантомная запаска SP в v1.1.3](01-phantom-spare.md): мусорные `SENSOR_XX` сейчас получают ложный SENSOR_LOST и переводят всё приложение в Alert.
- Из [Как защитить парсер AA55 от мусорных кадров](04-aa55-parser-hardening.md): «нет сигнала» = бит `0x20`, приходит флагом `noSignal`; кадр `09` разбирается, `0x07` шлётся при открытии.
