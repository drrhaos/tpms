## Question

Сейчас один кадр за порогом сразу даёт тревогу, а один нормальный — снимает её. Вводить ли подтверждение (N кадров подряд / окно времени) и гистерезис порогов? Разное ли оно для LOW_PRESSURE (быстрая утечка важна), HIGH_PRESSURE, HIGH_TEMP, BATTERY_LOW и аппаратных флагов статуса? Где это живёт — `AlertEvaluator`, репозиторий или новый модуль.

## Подсказки

- Из [Как защитить парсер AA55 от мусорных кадров](04-aa55-parser-hardening.md): значения уже подтверждаются двумя одинаковыми кадрами за 5 с; биты статуса приходят флагами `noSignal`/`leak`/`lowBattery` — решить, какие тревоги из них следуют (`leak` кратковременный при откручивании/накручивании датчика, см. тикет 03).

## Resolution

Grilling с drhaos, 2026-10-20. Подтверждение «N кадров подряд» бессмысленно: ресивер повторяет кэш слота, а мусор уже отсекает фильтр «2 одинаковых кадра за 5 с» (тикет 04). Реальная проблема — дребезг у порога (шаг 3.44 кПа / 1 °C), поэтому решение — гистерезис при снятии и выдержка только для кратковременных флагов. Все правила ниже применяются к подтверждённым чтениям.

**Показ тревоги:**

| Тревога | Источник | Когда показывается |
|---|---|---|
| LOW_PRESSURE | `pressure < low` | сразу |
| LOW_PRESSURE | флаг `leak` (0x08) | если флаг держится ≥ 15 с подряд; чтение без флага сбрасывает отсчёт |
| HIGH_PRESSURE | `pressure > high` | сразу |
| HIGH_TEMP | `temp > highTemp` | сразу |
| SENSOR_LOST | флаг `noSignal` (0x20) | сразу |
| BATTERY_LOW | флаг `lowBattery` или `battery < 10 %` | сразу |

**Снятие тревоги** (константы, не настройки):
- LOW_PRESSURE — при `pressure ≥ low + 10 кПа` (и без удерживаемого `leak`);
- HIGH_PRESSURE — при `pressure ≤ high − 10 кПа`;
- HIGH_TEMP — при `temp ≤ highTemp − 3 °C`;
- BATTERY_LOW — залипает: снимается, только если флаг сброшен **и** заряд ≥ 15 % (или неизвестен) непрерывно ≥ 10 мин;
- SENSOR_LOST — первым подтверждённым чтением без `0x20`.

Порядок приоритета прежний: флаги ресивера → пороги → батарея; для запаски пороги по-прежнему пропускаются.

**Таймаут по приходу кадров** (`checkSensorTimeouts`, `sensorTimeoutMs`) больше **не даёт SENSOR_LOST**: для AA55 он не видит мёртвый датчик, а для HID (передача ~1 раз в минуту на стоянке) даёт ложные тревоги. Устаревание — состояние «данные старые», а не тревога; критерий и показ — в тикете [Как определять потерю датчика, если ресивер повторяет последнее значение](10-sensor-loss-detection.md).

**Где живёт:**
- `AlertEvaluator` остаётся чистым: `evaluate(sensor, thresholds, memory, now) → (alertType, memory')`, где `memory` — прошлая тревога и начала отсчётов (`leak` с, «батарея в норме» с). Это шов для unit-тестов.
- Память по id датчика хранит `TpmsRepository` (рядом с `_sensors`): переживает переоткрытие сессии, на диск не пишется; удаляется вместе с датчиком (например, при выключении запаски).
- `FrameDecoder` тревоги больше не вычисляет — только парсер → валидатор → фильтр подтверждения.

**Следствия для карты:** тикет 10 сужен до критерия и показа «данные старые»; туман «Где показывать тревоги» стал тикетом [Нужны ли отдельные уведомления о тревогах](15-alert-notifications.md).
