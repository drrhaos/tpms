## Question

Парсер трактует байт STATUS: `0x80` = нет сигнала, `0x08` = утечка (→ LOW_PRESSURE независимо от давления), `0x10` = низкая батарея; коды шин `00/01/10/11/05`; давление ×3.44 кПа, температура −50. Откуда эти значения и верны ли они для распространённых USB TPMS-донглов (CH340, «TPMS 100-A1», Deelife/MU7J, донглы для Teyes/FYT)?

Найти публичные описания/реверс протокола (GitHub, форумы 4pda/XDA, драйверы FYT), другие поля статуса, другие типы кадров (длины ≠ 8), формат ответа на команды `0x19`/`0x07`.

Результат: таблица «поле → значение → источник», расхождения с текущим кодом.

## Assets

- Находки исследования: [docs/research/aa55-status-flags.md](../../research/aa55-status-flags.md)

## Resolution

Формат кадра, XOR-чексумма, давление ×3.44 кПа, температура −50 °C и коды шин `00/01/10/11/05` в коде **верны** (6+ независимых источников, живые дампы).

Расхождения, важные для следующих решений:
- Бит «нет сигнала» — **`0x20`, а не `0x80`** (декомпиляция APK `com.tpms`, tomaskovacik, DreamOnTheGo; `0x80` только у cedricp).
- `0x08` (утечка) реален, но **кратковременный**: появляется при откручивании или накручивании датчика → нужен в тикете о подтверждении тревог.
- `0x10` — только флаг низкого заряда; процентов в протоколе нет (наши 5/50 % выдуманы).
- Ресивер **бесконечно повторяет последнее значение** каждого слота → таймаут по приходу кадров не ловит мёртвый датчик. Слот `05` без датчика шлёт **фиктивное значение** (`46 46` / `49 53`); надёжный признак отсутствия — ответ `55 AA 09 05 00 00 00 ..` на запрос ID `0x07`.
- Ресивер шлёт и другие кадры (`09` — ID датчика с позициями `01..05`, `06 18`, `07 30`, …); парсер их сейчас отбрасывает.
- Публичного реверса донглов Teyes / «TPMS 100-A1» нет; бит «нет сигнала» стоит проверить на железе.
