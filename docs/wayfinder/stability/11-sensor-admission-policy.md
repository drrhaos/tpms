## Question

Сейчас любой распарсенный датчик попадает в карту `sensors`, а `WheelLayout.orderedSlots` при пустом маппинге раскладывает их по слотам через fallback `elementAtOrNull` — так мусорный или лишний датчик занимает чужое колесо, а 5-й датчик HID нельзя отличить от колеса при выключенной запаске. Какая политика допуска: только датчики с известными метками FL/FR/RL/RR/SP для AA55; для HID (метки нет) — обязательная привязка в настройках, автопривязка первых N, «карантин» новых ID до подтверждения? Где она живёт (парсер, репозиторий, `WheelLayout`) и как связана с UI привязки колёс из карты настроек.

## Подсказки

- Из [Как защитить парсер AA55 от мусорных кадров](04-aa55-parser-hardening.md): AA55 больше не выдаёт `SENSOR_XX` (неизвестные коды отбрасываются); кадр `09` даёт ID датчика по слоту и признак «слот пуст» — можно использовать для допуска.

- Из [Откуда фантомная запаска SP в v1.1.3](01-phantom-spare.md): fallback по индексу (`WheelLayout.kt:32`) оставить только для HID с пустой меткой и без дублей; запись в репозиторий через `_sensors.update {}`.

## Resolution

Grilling с drhaos, 2026-10-24. На момент решения неизвестные коды AA55 уже отбрасывались (04), а `WheelLayout` подставлял в свободные слоты только датчики без метки — по порядку появления.

**Слот по умолчанию («Авто»):**
- AA55/Deelife — по метке ресивера `FL/FR/RL/RR/SP`;
- HID — по id: `SENSOR_01..04` → `FL..RR`, `SENSOR_05` → `SP` (байт 0 кадра считаем позицией; **проверить на железе**);
- подстановки «по порядку появления» больше нет; датчик с другим id попадает на колесо только через привязку.
- `SP` — только при включённой запаске.

**Пустой слот AA55:** если последний ответ `09` (на `0x07` при открытии) для слота — «пусто», кадры этого слота не допускаются (любой слот, не только SP) — так фиктивное значение пустого слота 05 не становится запаской. Пока `09` не пришёл — допускаем как раньше. Периодический `0x07` не вводим.

**Ручная привязка — послотовая:** «Авто» = правило по умолчанию для этого слота; привязка меняет только свой слот; датчик, явно привязанный к слоту, уходит со своего слота по умолчанию (один датчик — один слот). Для любого протокола. Привязанный, но ещё не виденный датчик → слот пуст (без подстановки).

**Датчики вне слотов** — только для привязки: не влияют на состояние и тревоги, не пишутся в историю и снимок; живут в списке «виденные датчики» (последнее чтение) для UI привязки и диагностики.

**Пересчёт сразу:** репозиторий хранит последнее чтение каждого виденного датчика; набор колёс (`sensors`) выводится из него + привязки + запаски + пустых слотов AA55 и пересчитывается при смене настроек, без ожидания кадра (состояние и тревоги — тоже).

**Где живёт:** чистый `WheelAssignment` в `domain/` (виденные чтения, привязка, запаска, пустые слоты → «слот → датчик»); `WheelLayout.orderedSlots` теряет fallback и читает эту карту; UI, виджеты, диагностика берут один результат.

**UI привязки (минимум, редизайн вне карты):** перебор по всем виденным датчикам, рядом с id — последнее давление, чтобы датчик можно было опознать; остаётся в расширенном режиме.

**Уточнено при ревью реализации (drhaos, 2026-10-25):**
- Датчик, привязанный к `SP` при выключенной запаске, не показывается нигде и уходит со своего слота по умолчанию; привязка `SP` экспортируется/импортируется всегда (все 5 слотов).
- Валидные кадры датчиков вне слотов поддерживают «свежесть» соединения (`lastValidFrameAtMs`, тикет 10) — это здоровье связи, не состояние колёс.
- Виденные датчики вне колёс и без привязки, молчащие > 30 мин, удаляются вместе с памятью тревог — только при приходе живого кадра (не при восстановлении снимка и не при смене настроек).
