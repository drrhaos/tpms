## Question

После переэнумерации или холодной загрузки разрешение на донгл может пропасть, а сервис сам его не запрашивает; ответ на запрос сейчас всегда false из-за `FLAG_IMMUTABLE` ([Хронология от пробуждения магнитолы до первого кадра](09-wake-timeline.md), B4/B7). Варианты: онбординг требует «использовать по умолчанию для этого устройства» (минус — MainActivity всплывает при каждом подключении, B15); сервис сам запрашивает разрешение через уведомление; оба. Что делать на устройствах, где диалог «по умолчанию» не запоминается.

## Resolution

Grilling с drhaos, 2026-10-25. На момент решения B4 уже исправлен (`FLAG_MUTABLE`, выданное разрешение будит сервис как attach); attach без разрешения уже показывал уведомление и запрос.

**Сервис нашёл донгл без разрешения** (холодная загрузка, пропущенный attach — B7):
- сам вызывает `requestPermission` **один раз на появление донгла** (по `deviceName`); после отказа больше сам не спрашивает до следующего появления донгла или тапа пользователя;
- постоянное уведомление «Нужно разрешение USB» с кнопкой повторного запроса — в **канале состояния, без звука**, не смахивается, пока проблема есть (не канал тревог);
- статус как USB-ошибка: новый `UsbFault.NO_PERMISSION` в шапке и подстроке постоянного уведомления (тот же путь, что `DONGLE_SILENT`/`USB_STUCK`); тап по шапке — повторный запрос; снимается, когда разрешение есть или донгл пропал.

**«По умолчанию для этого USB-устройства»** (B15): фильтр `USB_DEVICE_ATTACHED` переезжает с `MainActivity` на невидимую activity-трамплин (будит сервис как attach и сразу закрывается) — ассоциация и переживание переэнумерации остаются, `MainActivity` не всплывает. Проверить на железе, не мигает ли пустой кадр.

**Онбординг, шаг USB:** подсказка «отметьте Использовать по умолчанию — иначе после каждого сна придётся подтверждать»; не блокирует (проверить галку нельзя).

**Прошивки, не запоминающие «по умолчанию»:** ничего сверх автозапроса (без root не закрепить); в диагностику — счётчик запросов разрешения.
