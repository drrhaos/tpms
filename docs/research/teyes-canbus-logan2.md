# Данные CAN-шины на Teyes: что можно получить на CC3 + Renault Logan 2 (2019, базовая комплектация)

Вопрос: может ли приложение получать параметры автомобиля с CAN-шины через магнитолу Teyes и что из этого
реально доступно на конкретной машине — CC3, Renault Logan 2019 (2G, рестайлинг), базовая комплектация,
CAN-декодер установлен, руль и задний ход на магнитоле работают.

Ограничения: железа здесь нет, официального SDK FYT нет. Протокол восстановлен по декомпиляции сторонними
проектами (первичные источники — их репозитории на GitHub), сведения о Logan 2 — с форумов владельцев (вторичные).

## Как данные попадают к приложению

```
CAN авто → CAN-декодер (для Logan 2 — Hiworld) → UART → MCU → com.syu.ms (разбор по профилю авто) → binder IPC com.syu.ipc → приложения
```

Сырой CAN приложению недоступен: ни SocketCAN, ни прямого доступа к декодеру. Приложение видит только то, что
декодер передал в MCU **и** что `com.syu.ms` разобрал по выбранному профилю.

## Протокол `com.syu.ipc`

| Что | Значение | Источник | Уверенность |
|---|---|---|---|
| Сервис | `Intent().setClassName("com.syu.ms", "app.ToolkitService")`, явный bind | [ram-phoenix-hu `docs/CANBUS-IPC.md`](https://github.com/beauahill/ram-phoenix-hu/blob/main/docs/CANBUS-IPC.md) | высокая |
| Манифест | Android 11+: `<queries><package android:name="com.syu.ms"/></queries>`, иначе bind молча не срабатывает. CC3 — Android 10, но запрос нужен для CC3 2K/CC4 | там же | высокая |
| Разрешения | Не нужны: сервис не проверяет вызывающего | [wk2-climate](https://github.com/chrisuthe/wk2-climate) | средняя |
| `IRemoteToolkit` | txn 1 `getRemoteModule(int module) → IBinder` | ram-phoenix-hu | высокая |
| `IRemoteModule` | txn 1 `cmd(code, int[], float[], String[])` oneway; txn 2 `get(code, …) → {hasObj, int[], float[], String[]}`; txn 3 `register(IModuleCallback, code, update = 1)` oneway; txn 4 `unregister(cb, code)` | ram-phoenix-hu, [XDA](https://xdaforums.com/t/developing-an-obd2-canbus-data-logger.4454275/) | высокая |
| `IModuleCallback` | txn 1 `update(code, int[], float[], String[])` oneway | там же | высокая |
| Дескрипторы | Каждый parcel начинается с `writeInterfaceToken("com.syu.ipc.IRemoteToolkit" / "…IRemoteModule" / "…IModuleCallback")`, с другим дескриптором сервис не отвечает. AIDL не нужен, клиент пишется вручную | ram-phoenix-hu, XDA | высокая |
| Модули | MAIN 0, RADIO 1, BT 2, DVD 3, SOUND 4, IPOD 5, CANBUS 7, DVR 9, STEER 10, OBD 12, CAN_UP 14, GSENSOR 17, SENSOR 19, ADAS 20 | ram-phoenix-hu | высокая |
| Чтение | Рабочий путь — только `register`: при регистрации сервис сразу отдаёт кэш, дальше шлёт изменения. `get` у wk2-climate всегда пустой. Сигналы, которые сервис ещё не получил, приходят позже — нужна повторная регистрация | wk2-climate | средняя |
| Потоки | Колбэки разных модулей приходят параллельно на binder-потоках | wk2-climate | высокая |

### Коды, не зависящие от машины (модуль MAIN)

| Код | Смысл | Уверенность |
|---|---|---|
| 12 `U_BACKCAR` | `ints[0] == 1` — задний ход включён, `0` — выключен | высокая (подтверждено вживую на RAM) |
| 50 | ACC on | низкая (только статический анализ) |
| 22, 23, 24, 81 | парктроники, траектории, зеркало, камера 360 | низкая |
| 41 | угол руля | низкая |

### Коды модуля CANBUS — **зависят от профиля**

- Профиль: `get(CANBUS, 1000)` (`U_CANBUS_ID`). Пример с RAM: `CAR_455_…` = 6357447 = `0x61_01C7`, то есть,
  видимо, `(вариант << 16) | номер машины` (0x1C7 = 455). Не проверено.
- В профиле RAM: 0–5 двери, 10–37 климат, 98–136 «сырые» данные бортового компьютера (`U_CARINF_*`), где
  предположительно лежат давление в шинах и пробег. У другого профиля номера и набор другие; таблиц
  соответствия нет, их снимают вживую.

| Данные | На базовой комплектации | Источник | Уверенность |

| Кнопки руля | Работают — ради колёсика на подрулевом джойстике декодер в базе в основном и ставят | там же, [drive2, Logan 2019, CC2 Plus](https://www.drive2.ru/l/574087182650706122/) | высокая |
| Задний ход | У владельца Access по CAN **не пришёл**, сигнал взят проводом с ЦЭКБС. У нас работает — откуда, CAN или провод, неизвестно | drive2 (2020) | средняя |
| Двери | Не работают (объяснение комментатора: нет модуля BIC) | drive2 (2019) | средняя |
| Климат | В меню нули: нет кондиционера | drive2 (2019) | высокая |
| Скорость, обороты, температура за бортом, топливо, пробег | Упоминаний нет | — | — |
| Штатный TPMS | На Logan 2 нет | — | высокая |

Вывод: на этой машине через `com.syu.ms`, скорее всего, придут только кнопки руля, возможно задний ход и,
возможно, ACC. Параметров, полезных для давления в шинах (скорость, забортная температура), может не быть
вовсе — это зависит от того, что прошивка Hiworld для Renault пересылает в MCU. Проверяется только на машине.

## Что из этого полезно приложению

| Идея | Нужно с шины | Ценность |
|---|---|---|
| Доп. триггер пробуждения рядом с `SCREEN_ON` ([stability](../specs/stability.md)) | MAIN 50 (ACC) | высокая, если код работает |
| Поправка давления на холод | температура за бортом | средняя |
| `SENSOR_LOST` только в движении | скорость | средняя |
| Штатный TPMS как источник данных | давление в шинах | для Logan — нет |
| Вывод скорости, оборотов, топлива | — | низкая: Teyes показывает это сам |

Если CAN на Logan окажется пустым, альтернатива для скорости и температуры — OBD2 (ELM327 по Bluetooth;
в `com.syu.ms` есть модуль OBD 12, что он отдаёт — не изучено). Температура всасываемого воздуха —
приблизительная замена забортной, и только на холодном двигателе.

## План проверки на CC3 + Logan

1. **Без кода (adb).** Записать профиль CANBUS из настроек (производитель / машина / вариант). Затем:
   `dumpsys activity services com.syu.ms`, `getprop | grep -iE 'can|fyt'`, `logcat | grep -iE 'canbus|syu'`
   при включении зажигания, заднего хода и начале движения. Цель — понять, пишет ли `com.syu.ms` в лог
   принятые кадры.
2. **«CAN-разведка» в сервисном меню** (только Teyes, отдельный экран, в рабочий путь сервиса не встраивается).
   Bind к `ToolkitService`, `get(CANBUS, 1000)`, `register` на все коды 0–200 модулей MAIN и CANBUS,
   в диагностический лог пишется каждый `update` (модуль, код, массивы, время). Сценарий: зажигание →
   заведённый двигатель → задний ход → поездка с остановками → открыть двери → выключить зажигание → сон →
   пробуждение.
3. **По логу** решить: ACC — в триггер пробуждения; скорость / температура — в задачу о логике тревог;
   пусто — закрыть CAN для Logan и при необходимости изучить OBD.

## Открытые вопросы

1. Профиль CANBUS на этой машине (производитель декодера / профиль / вариант) и значение `U_CANBUS_ID`.
2. Задний ход на этой машине — по CAN (`MAIN 12` придёт) или проводом?
3. Приходит ли MAIN 50 (ACC on) после выхода из сна раньше `SCREEN_ON` и надёжнее ли он?
4. Переживает ли binder-соединение с `com.syu.ms` сон, или после пробуждения нужен повторный bind
   и повторная регистрация?
5. Отдаёт ли прошивка Hiworld для Renault хоть что-то сверх руля и заднего хода (скорость, температура)?
